API Reference — every endpoint, live

Everything the OzSEO Toolkit UI does, you can do over plain HTTP JSON — free, no key required (PageSpeed has an optional key). Every endpoint below has a live example: press Run and see the real response from this server.

health audit perf speed backlinks GET backlinks POST

INFOConventions

Applies to every endpoint on this page.

  • All responses are JSON — including errors, which always use {"error": "message"}, never an HTML error page.
  • URLs are flexible: example.com, example.com.au and full https://… all work.
  • Audits time out after 50s server-side; plan client timeouts above that.
  • GET /api/audit snapshots each host (last 10 runs) and returns a drift object when a previous audit exists.
  • On Cloudflare Workers the engine is identical, except DNS/TLS checks degrade to info. The backlink directory persists in a bound KV namespace (BACKLINKS) — same validation, dedupe and response shapes as the Node version.

GET/api/health

Liveness probe. Used by the web UI to detect a sleeping server and by start.sh to verify startup.

Parameters

None.

Response

{
  "ok": true,
  "uptime": 42            // server uptime in whole seconds (Node)
}
On Cloudflare Workers the response additionally contains "runtime": "cloudflare-workers".

    

  


  
  

    
GET/api/audit

    
The full audit engine: fetches the page and runs 90+ checks across 8 weighted categories, returning scores, every individual check, SERP preview data, keywords, DNS/TLS/RDAP facts and drift vs the previous run.

    
Parameters

    

      
ParamRequiredDescription

      
urlrequired
Site or page to audit. Scheme optional.

    

    
Response — top level

    
{
  "requested": "example.com",        // what the caller sent
  "url": "https://example.com/",     // final URL after redirects
  "host": "example.com",
  "fetchedAt": "2026-09-12T08:30:00.000Z",
  "httpStatus": 200,
  "ttfb": 231,                       // ms to first byte
  "pageSizeKb": 1,
  "overall": 64,                     // 0–100, weighted across groups
  "groups": { ... },                 // 8 categories, see below
  "checks": [ ... ],                 // every check, see below
  "drift": { ... }                   // only when this host was audited before
}

    
groups — the 8 scored categories

    
"groups": {
  "seo":         { "label": "On-Page SEO",        "score": 61, "pass": 6, "warn": 5, "fail": 3, "total": 14 },
  "geo":         { "label": "GEO / AI SEO",       ... },
  "technical":   { "label": "Technical & Health", ... },   // weights: seo 22, geo 18, technical 16,
  "performance": { "label": "Speed & Performance", ... },   // performance 12, security 10, content 8,
  "security":    { "label": "Security & Trust",   ... },   // mobile 7, local 7
  "mobile":      { "label": "Mobile",             ... },
  "content":     { "label": "Content Quality",    ... },
  "local":       { "label": "Local SEO (Australia)", ... }
}

    
checks[] — every individual check

    
{
  "group": "seo",              // key of groups above
  "name": "Title tag",
  "status": "pass",            // "pass" | "warn" | "fail" | "info"
  "message": "Title is 44 characters — inside the 10–60 sweet spot.",
  "fix": ""                    // plain-English fix, non-empty on warnings/failures
}

    
Other notable fields

    
    
      
  • serp — { title, description, url } Google-snippet preview.
    • 
      
  • keywords — top 12 as { word, count, density } (density in %).
    • 
      
  • readability — Flesch Reading Ease 0–100, or null if too little text.
    • 
      
  • aiCrawlers[] — for 12 AI bots: { bot, vendor, blocked, rule } from robots.txt.
    • 
      
  • ssl — { issuer, validTo, daysLeft, protocol } (https only).
    • 
      
  • dns — { ip, ipv6, mx[], ns[] }; domain — { registered, registrar, ageYears } via RDAP.
    • 
      
  • states — AU mentions, e.g. { "NSW": ["new south wales", "sydney"] }.
    • 
      
  • links — { internal, external, checked, broken: [{status, url}] } (sampled).
    • 
      
  • headings — first 30 heading texts.
    • 
    

    
drift — vs the previous audit of the same host

    
"drift": {
  "previousAt": "2026-09-12T06:58:52.246Z",
  "previousOverall": 65,
  "delta": -1,                       // overall change since last run
  "groups": { "technical": -5, ... } // per-category change
}

    
Heavy endpoint: the engine visits the target site, robots.txt, sitemap, and samples links. Budget several seconds; the hard limit is 50s.

    

      

        
        
      

      

      

    

  


  
  

    
GET/api/perf

    
Built-in performance probe — three real fetches of the HTML document from this server. No external API, always available.

    
Parameters

    

      
ParamRequiredDescription

      
urlrequired
Page to probe.

    

    
Response

    
{
  "samples": 3,          // runs that succeeded (up to 3)
  "ttfbAvg": 240,        // ms, average across runs
  "ttfbBest": 189,       // ms, fastest run
  "htmlKb": 22,          // HTML document size
  "encoding": "br"       // content-encoding: br | gzip | none
}

    
Unreachable site → 400 with {"error": "Could not reach that site."}.

    

      

        
        
      

      

      

    

  


  
  

    
GET/api/speed

    
Google Lighthouse run through the free PageSpeed Insights API. Rate-limited by Google — retry after a minute on 429-style errors. Optional PAGESPEED_API_KEY env var on the server raises quota.

    
Parameters

    

      
ParamRequiredDescription

      
urlrequired
Page to test.

      
strategyoptional
mobile (default) or desktop.

    

    
Response

    
{
  "url": "https://example.com",
  "strategy": "mobile",
  "fetchTime": "2026-09-12T08:40:11.000Z",
  "scores": {                       // 0–100 each, or null
    "performance": 92, "accessibility": 87,
    "bestPractices": 83, "seo": 91
  },
  "metrics": {                      // value = ms (cls: unitless), display = human string
    "fcp":  { "value": 1230, "display": "1.2 s" },
    "lcp":  { "value": 2010, "display": "2.0 s" },
    "tbt":  { "value": 60,   "display": "60 ms" },
    "cls":  { "value": 0.01, "display": "" },
    "si":   { "value": 1540, "display": "1.5 s" },
    "tti":  { "value": 2100, "display": "2.1 s" }
  },
  "lcpElement": "<img src=\\"hero.webp\\">",   // snippet or null
  "opportunities": [                // up to 6, biggest saving first
    { "title": "Serve images in WebP", "saving": 450, "description": "…" }
  ],
  "reportUrl": "https://pagespeed.web.dev/analysis?url=…"  // full Google report
}

    
This endpoint proxies Google and can take 30–60s+; failures surface as JSON errors such as Google PageSpeed rate limit reached….

    

      

        
        
        
      

      

      

    

  


  
  

    
GET/api/backlinks

    
The community backlink & blogger directory. Newest listings first.

    
Parameters

    

      
ParamRequiredDescription

      
stateoptional
Filter: NSW VIC QLD WA SA TAS ACT NT (case-insensitive).

      
categoryoptional
Filter: Blogger, Business, Directory, News / Media, Community, Other.

      
limitoptional
Max listings per page. Default 50, capped at 100 (values >100 or ≤0 fall back to the default).

      
offsetoptional
Listings to skip from the newest — combine with limit to page: ?limit=50&offset=50. Ignored when after is used.

      
afteroptional
Cursor: a listing id. Returns listings strictly older than that id, newest first. Unlike offset, pages never shift when new listings arrive mid-scroll — pass nextCursor from the previous response as ?after=… for the next page.

    

    
Response

    
{
  "total": 120,                  // ALL listings, before filtering
  "offset": 0,                   // echo of the request's offset
  "limit": 50,                   // effective page size (after cap)
  "hasMore": true,               // more pages available after this one
  "nextCursor": "mtz0g7a7nljc",  // last id on this page; pass as ?after= for the next page (null on the last page)
  "listings": [
    {
      "id": "kpx8z1ab2c3d",
      "name": "Sydney Garden Blog",
      "website": "https://example.com.au",
      "state": "NSW",
      "category": "Blogger",
      "description": "…",           // ≤ 400 chars
      "lookingFor": "…",            // ≤ 200 chars, may be ""
      "addedAt": "2026-09-12"
    }
  ]
}

    
Submitter emails are collected at submission time (validated, stored for the operator) but are never returned by any endpoint — listings contain no email field.

    

      

        
        
        
        
      

      

      

    

  


  
  

    
POST/api/backlinks

    
Submit a listing. Body must be JSON. Stored in data/backlinks.json (cap: 500 listings; duplicate websites rejected by hostname).

    
Request body

    

      
FieldRequiredValidation

      
namerequired
2–80 chars.

      
websiterequired
Valid URL, scheme optional, hostname must contain a dot.

      
emailrequired
Valid email format.

      
staterequired
One of the 8 AU state/territory codes.

      
categoryoptional
Defaults to Other if not an exact category match.

      
descriptionrequired
20–400 chars.

      
lookingForoptional
≤ 200 chars.

    

    
Responses

    
200  { "ok": true, "entry": { ...same shape as GET listings... } }
400  { "error": "Please enter a valid website URL." }   // any validation failure
409  { "error": "That website is already listed." }
400  { "error": "Directory is full at the moment — please try again later." }
429  { "error": "Submission limit reached for this hour (3 per hour per IP) — please try again later." }
     // or: "Please wait at least 30 seconds between submissions."

    
Anti-spam quota per client IP: max 3 successful submissions per rolling hour, and at least 30s between submissions. Failed validation attempts don't count. Workers responses include a Retry-After header on 429.

    
Example

    
curl -X POST http://localhost:3000/api/backlinks \
  -H "Content-Type: application/json" \
  -d '{"name":"My Site","website":"mysite.com.au","email":"me@mysite.com.au",
       "state":"VIC","category":"Business","description":"Melbourne plumbing services directory listing.",
       "lookingFor":"Guest posts"}'

    
No live button here on purpose — it would write a listing to this server's directory. Use the form on the Free Backlinks page instead.
